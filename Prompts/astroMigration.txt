You are an expert Web Developer specializing in Astro, React, and DevOps. We are migrating a legacy plain HTML/CSS personal website into a modern, maintainable Astro project using the Islands Architecture. 

Our core goals are to eliminate code duplication, create a robust type-safe content system, set up React specifically for interactive components, and ensure the entire project is production-ready and Dockerized.

Please execute the following migration plan step-by-step. Stop and ask for my confirmation after completing each major phase before moving on to the next.

### Phase 1: Project Initialization & Layouts
1. Initialize a new Astro project and install the `@astrojs/react` integration.
2. Analyze the current plain HTML files and identify duplicate code (e.g., `<head>`, `<nav>`, `<footer>`).
3. Create a reusable `BaseLayout.astro` in `src/layouts/`. It must include:
   - Proper SEO metadata props (title, description).
   - The shared navigation and footer.
   - A `<slot />` for page content.
4. Move our global CSS files into `src/styles/` and import them into `BaseLayout.astro`.

### Phase 2: Content Collections (The Data Layer)
We have multiple markdown-driven content types (Portfolio Projects, App Privacy Policies, and Documentation). We must use Astro Content Collections to ensure type safety.
1. Create `src/content.config.ts` using Astro's `defineCollection` and Zod schemas (`z.object()`).
2. Define the following schemas:
   - `projects`: title, description, date, techStack (array of strings), coverImage (optional).
   - `policies`: title, lastUpdated (date).
3. Migrate the existing privacy policies and project text into Markdown files under `src/content/projects/` and `src/content/policies/`.
4. Create dynamic routes in `src/pages/projects/[slug].astro` and `src/pages/policies/[slug].astro` using `getCollection()` and `render()` to display the content.

### Phase 3: Static Pages & React Islands
1. Convert the remaining static HTML pages (like `index.html`, `about.html`, `cv.html`) into `.astro` pages in `src/pages/`, wrapping them in `<BaseLayout>`.
2. Embed the React search component into the appropriate `.astro` page using the `client:load` or `client:idle` directive so it hydrates properly on the client. 

### Phase 4: Quartz / Obsidian Integration Setup
For my University Notes (built with Quartz):
1. Configure a script or pipeline in `package.json` to generate the Quartz build.
2. Output the Quartz build directly into Astro's `public/notes/` directory, so that Astro simply serves it statically under the `/notes` path without trying to bundle it.

### Phase 5: SEO, Metadata & Polish
1. Generate a standard `robots.txt` file in the `public/` directory.
2. Ensure placeholder favicons (`favicon.ico` and `favicon.svg`) are placed in the `public/` directory and properly linked in `BaseLayout.astro`.
3. Install and configure the `@astrojs/sitemap` integration to automatically generate a `sitemap.xml` for search engines.
4. Add basic Open Graph (OG) tags to the `<head>` in `BaseLayout.astro` for better social sharing previews.

1. Create a multi-stage `Dockerfile` in the root directory.

### Rules & Constraints:

- Ensure all React components use `.tsx` or `.jsx` file extensions, and Astro files use `.astro`.
- Use semantic HTML and keep CSS class structures clean.
